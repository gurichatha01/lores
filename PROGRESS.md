- Brief 2 follow-up (branch `brief-2-pack`): the report/unlock entitlement store is now durable and serverless-safe. Previously `lib/entitlements.ts` kept generated reports + their authorized flag in server memory, so on Vercel a report generated on one instance was invisible to the order/verify/spend call on another (wrongly "not found / still locked" even after a real payment). Now the entitlement state lives in Supabase (`reports` + `report_orders`, migration `0002_report_entitlements.sql`, RLS on + service-role only), so every instance shares it. A memory fallback with identical semantics activates only when Supabase is unconfigured (local single-instance dev + tests, which don't load `.env`).
- Privacy-preserving by design: the durable store holds ONLY a reference — the report id, order→report bindings, pack-order intent, and the authorized boolean. The report CONTENT (which quotes real chat messages) never touches the DB; the browser keeps it in sessionStorage and renders it once `/api/report-access` confirms the unlock. This keeps "never your chats, never your reports" honest. Consequently `/api/report` (server content delivery) was removed and `ReportPageClient` now confirms authorization + renders its own content.
- All entitlement functions became async; `generate` now calls `registerReport(id)` (a reference row, not content), and `order`/`verify`/`report-access`/`spend` await the store. `storeGeneratedReport`/`getAuthorizedReport`/`consumePackOrder` were removed; `authorizeOrder`/`authorizeReport` do idempotent boolean updates (no race). Scope fences honored: `pack_credits` ledger/spend, `PRICING`, the ₹99 single's rendered output, and report layout/PDF/prompts are all unchanged.
- Verified: 118 unit tests pass (entitlement tests rewritten for the async model, exercising the in-memory fallback); typecheck + build green; a cross-process test (Process A writes entitlement state → a fresh Process B with empty memory reads/authorizes it via Supabase) passes — the exact serverless bug; and the full single flow through the live Supabase-backed endpoints (order → unknown-report 409 → pre-pay locked → real-HMAC verify → post-pay authorized, persisted in `reports.authorized`) passes.
